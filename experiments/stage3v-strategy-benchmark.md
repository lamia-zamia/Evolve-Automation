# Stage 3V — strategy benchmark

## Result

The browser closure defect is fixed and covered by a real Chromium contract test. The benchmark search did **not** find a safe consequential choice to compare. Extending Stage 3R scenario B from 4,000 to 8,000 periods exposed a Titanium gate, but no currently affordable Research choice or enabled production lever that would give a defensible second alternative. No intervention was run and no release behavior changed.

## Browser contract and authority

`experiments/stage3s-strategy-pilot.mjs` stringifies its test selector into the page. The selector previously closed over the Node-imported `readFreshGoalResourceStock`, which does not exist in that browser scope. The selector now lives in the isolated `stage3v-candidate-selector.mjs` module and receives `readFreshStock` explicitly. The experiment bundle independently injects both function bodies into the test hook. `tests/experiments/stage3v-candidate-selector-chromium-test.mjs` runs an unmodified DeadSpace page in Chromium with a current-style Research offer, a 10 Steel live root holding, and a 250 Steel native price; it asserts the selector reaches the stock branch and returns the expected 240 Steel shortfall. The focused contract passed.

The selector’s `actionId` is a proposed native element id. The test adapter checks that it is a nonempty string and that its `actionId:generation` text is internally consistent, then compares caller-supplied freshness values. Those checks do not independently read the current native offer or establish the live control binding, current generation, price, or native authorization. Native Research remains the executor; current native eligibility, affordability, and the bound control remain authoritative at execution.

## Smallest strategy contract and next implementation

Keep strategy selection above native execution. A candidate evaluation needs:

1. **Safety facts:** current native action/offer identity, binding generation, native price and affordability; responsible owner permission; fresh state; protected current spending commitments; and the native executor as the only action issuer.
2. **Goal facts:** the selected prestige goal, the current native prerequisite/eligibility evidence, the next meaningful milestone, and the candidate’s link to that milestone. A prerequisite route is evidence, not proof that the ordinary Research owner will select the action.
3. **Economic effects:** current holdings and rates, storage capacity, production and construction changes, the competing activity that loses resources, and any reservation or demand displaced. Missing or partial facts remain labeled partial.
4. **Uncertainty and result:** an expected milestone-time range with its assumptions, confidence/uncertainty, deadlock or starvation risk, and measured execution overhead. Do not treat maximum production or earliest purchase of one technology as the objective.

For a frozen fixture, compare a no-intervention baseline and one isolated test-only choice from the current native alternatives. Report a score vector rather than inventing weights: periods to the next meaningful milestone, eventual periods to selected prestige completion, resource opportunity cost, production/construction and technology consequences, deadlock/starvation risk, and execution overhead. The primary ordering is progress toward the selected prestige goal; resource output is supporting evidence. Stage 3R’s C result remains a warning: Steel Containers came earlier, but Industrialization was later than balanced B and had not arrived by p4000.

**Next implementation recommendation:** do not add a production strategy or new setting yet. First find or characterize a real checkpoint with two currently safe native alternatives and a measurable downstream milestone. The existing aggregate `requestedQuantity` cannot prove a complete bounded spending-request sample because it drops request provenance and source-specific completeness. If that evidence becomes the blocker, add a narrow immutable current-spending-request observation with explicit source coverage, completeness/reasons, and freshness; exclude project-storage targets, capacity, future commitments, and unobserved sources. Keep `sampleExact()` as-is. Once a suitable choice exists, the smallest strategy slice is a test-only evaluator for that one choice, with the current native owner still executing it.

No test-only strategy intervention was justified in Stage 3V, and no release setting, planner, or runtime wiring changed.
